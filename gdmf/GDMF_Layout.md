# GDMF - Graphic Device Minimalist Framework

## Layout

Each layer lives in its own subfolder; what stays at the root is what every
layer uses or what binds them together.

| Folder | Holds |
|--------|-------|
| `vulkan/` | The renderer core (`gdmf_vulkan.c/.h`), its internal header, and the per-platform surface files (`gdmf_surface_win32.c`, `_macos.c`, and for Linux the `_linux.c` run-time dispatcher over `_wayland.c` / `_x11.c`). |
| `textlayer/` | The text layer and its glyph data (`packedbitmaps.h`). |
| `sprites/` | The sprite layer, plus `gdmf_sprites_help.*`. |
| `tiles/` | The tile layer, plus `gdmf_tiles_help.*`. |
| `pixies/` | The pixie layer. |
| `shaders/` | GLSL sources, compiled SPIR-V, baked headers, and `spv2h.c`. |

At the root: `gdmf.c/.h` (bring-up and the canvas), `gdmf_colors.*` and
`gdmf_interactions.*` — cross-cutting services the layers call rather than
layers themselves — plus the window backends (`gdmf_window.h` and its
per-platform `gdmf_window_*.c`, with `gdmf_window_linux.c` probing at run time
so one Linux binary serves both Wayland and X11).

Layers include each other's headers unqualified (`#include
"gdmf_vulkan_internal.h"`), which works because the top-level Makefile puts
every layer folder on the include path (`GDMF_INCS`). A new layer folder needs
one entry added there. Code outside the engine reaches GDMF through
`fuselage.h`, which spells the paths out in full.

The `*_help.c/.h` files sit with the layer they wrap: the layer cores are
deliberately absolute-only, and the helpers are the relative (delta)
conveniences layered over them.

## Files that must not be deleted

### textlayer/packedbitmaps.h
Contains all 256 character glyphs for the text layer, packed at 2 bits per pixel (16×16px each).
**Generated by Edibima - do not edit by hand.** To update the typeface, open the source in Edibima and re-export this file.

### shaders/
The GLSL shaders for every GDMF layer (text, sprites, tiles, pixies, and the
mask-composite pass) plus the tool that bakes them in. Each shader exists in
three forms, and all are load-bearing:

`<name>.vert` / `<name>.frag` : GLSL source — edit these to change a shader.
`<name>_vert.spv` / `<name>_frag.spv` : the compiled SPIR-V.
`<name>_vert.h` / `<name>_frag.h` : that SPIR-V baked into a C header, `#include`d by the layer that uses it.
`spv2h.c` : the small tool that turns a `.spv` into its `.h`.

The whole chain is driven by the top-level Makefile: it compiles `.vert`/`.frag`
→ `.spv` with `glslc`, builds `spv2h` from `spv2h.c` on first use, and runs that
to produce the `.h`. Editing a shader and rebuilding regenerates the header
automatically — nothing external is needed beyond `glslc` (from the Vulkan SDK).
